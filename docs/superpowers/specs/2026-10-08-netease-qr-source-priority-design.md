# 网易云扫码登录与歌词来源优先级设计

## 目标

让手机发送端优先通过网易云网页式扫码流程建立账号会话；获取歌曲歌词时优先使用网易云，网易云无法提供可同步歌词时再查 LRCLIB。发送端需要明确显示当前歌词实际来自哪个来源。

## 当前项目背景

- Android 手机发送端通过通知媒体会话读取网易云当前歌曲，并通过蓝牙将歌曲、歌词和播放进度发给车机。
- 网易云密码和短信登录目前会触发 8821 等安全验证；扫码登录尚未实现。
- 当前歌词查询只配置网易云，LRCLIB provider 和 provider fallback 已被删除；歌词缓存不再读取旧记录。
- 网易云登录会话通过现有 `NetEaseSessionStore` 加密保存在手机。

## 方案选择

### 推荐：原生扫码界面调用网页扫码流程

在应用内获取扫码 key、生成二维码图片并轮询认证状态。它能将扫码成功得到的会话直接交给当前网易云请求客户端和加密存储。该流程参考公开客户端实现，但相关网易云接口不是网易云承诺稳定的第三方公开 API，接口或安全策略变化时可能失效。

### 后续增加：嵌入网易云网页登录 WebView

用户后续提出直接使用 `music.163.com` 网页登录，因此在二维码页增加“网页登录（当前设备）”备用入口。WebView 只允许 HTTPS 的 `163.com` 子域名导航；登录后从应用自己的 `CookieManager` 读取适用于 `music.163.com` 的 Cookie，确认其中有非空 `MUSIC_U` 后交给现有 Android Keystore 加密会话存储。系统浏览器的 Cookie 不共享给应用，因此登录必须在这个应用内页面完成。网易云网页结构、WebView 兼容策略或风控变化仍可能导致网页登录不可用。

## 登录交互

- 手机发送端“登录网易云”入口打开后默认显示二维码。
- 二维码由另一台已登录网易云的设备扫描并确认。密码登录和短信验证码登录保留为次要入口。
- 认证流程按获取 key、生成二维码、轮询检查状态执行；轮询间隔约 3 秒，并在页面关闭时取消。
- 状态码 800 表示二维码过期；801 表示等待扫码；802 表示已扫码、等待确认；803 表示授权成功。过期时提供重新生成按钮。
- 只有收到授权成功并获得有效 Cookie 后才调用 `NetEaseSessionStore` 保存会话；失败响应中的 Cookie 不得保存。
- 如果二维码认证返回 8821 或其它安全验证挑战，停止轮询并说明需要先在官方网易云音乐 App 完成验证。不得尝试规避或自动高频重试。
- 登录成功后收起登录表单，刷新当前歌曲歌词，与现有登录成功流程保持一致。
- WebView 使用 HTTPS、JavaScript 和 DOM 存储以兼容网易云登录页；不注入 JavaScript Bridge，禁用文件/内容访问和混合内容，只允许 `163.com` 域名内的 HTTPS 主页面导航。
- 只有 WebView 的网易云 Cookie 中出现非空 `MUSIC_U` 才会进入加密会话存储；界面不显示 Cookie，关闭登录页时停止轮询并销毁 WebView。
- 不增加从网页开发者工具复制或粘贴 Cookie/Token 的导入入口；网页登录由应用内 WebView 完成，扫码、现有密码和短信登录继续保留。

## 歌词来源和显示

- 查询顺序固定为网易云，然后 LRCLIB。
- 网易云无有效会话、没有找到可解析的时间戳歌词、接口异常或受限时，尝试 LRCLIB；LRCLIB 也仅接受有时间戳的歌词。
- 网易云返回有效时间戳歌词时立即采用，即使 LRCLIB 可能返回另一版本。网易云 YRC 逐字时间优先；只有 LRC 时继续使用已有逐句同步显示。
- 查询结果必须携带来源字段，例如 `NETEASE` 或 `LRCLIB`。发送端当前歌曲状态明确显示“歌词来源：网易云音乐”或“歌词来源：LRCLIB”；未匹配时不显示虚构来源。
- 来源字段在缓存读取时也必须可信。没有来源信息的旧缓存记录不得复用或标记为任一来源。
- 车机仍接收歌词和播放同步数据；首版只要求在手机发送端标记来源，不改变蓝牙协议或车机歌词外观。

## 错误处理和隐私

- 二维码过期可重新生成；网络失败显示可理解的错误并提供重试。
- 8821 表示网易云要求行为验证，扫码方式也不能保证绕过这一限制。
- 密码和短信凭据继续只在用户提交时短暂处理；登录 Cookie 继续用现有 Android Keystore 加密存储。
- 不引导用户从浏览器开发者工具提取会话 Cookie，也不在聊天中收集任何账号凭据。
- 不向 LRCLIB 发送网易云账号 Cookie，也不把任何登录凭据通过蓝牙发往车机。

## 验证

- 使用假传输覆盖二维码 key、图片响应、801/802 等待态、800 过期、803 成功、无 Cookie 失败、网络异常及 8821 挑战。
- 使用假 provider 覆盖网易云优先命中、网易云无结果后 LRCLIB 命中、网易云接口失败后回退、两边均无可用歌词、来源字段和缓存旧记录不误标。
- 运行完整单元测试并构建 Android 9 APK。真实账号扫码及手机蓝牙仍需用户设备验证；测试不得在自动化过程中触发真实登录或发送短信。

## 自审

- 未发现未定义的来源顺序：网易云始终优先，LRCLIB 仅在其无可用时间戳歌词时使用。
- 未发现登录数据路径歧义：成功 Cookie 进入现有加密存储，凭据不进入蓝牙消息或备用歌词请求。
- 范围限定为发送端认证、歌曲歌词 provider fallback、来源状态和相关测试；不改车机 UI 或蓝牙协议。

## 实施记录

- 手机端默认使用二维码登录，二维码在本地生成；密码和短信登录作为备用入口保留。
- 根据用户后续要求，二维码页增加当前设备网页登录；它只从应用内 WebView 的网易云 HTTPS Cookie 中读取 `MUSIC_U`，然后复用现有加密会话存储。
- 扫码授权只在状态 803 且响应含非空 `MUSIC_U` 时进入现有 Android Keystore 加密会话存储。
- 查询顺序已接入网易云 → LRCLIB。无网易云会话时也会继续 LRCLIB 查询；接收端蓝牙协议不变。
- 发送端状态展示实际命中的来源。无法给旧缓存补来源，因此继续禁用缓存读取。
- LRCLIB 查询请求只包含歌曲元数据；网易云会话 Cookie 不会发给备用歌词服务。
- 代码构建和自动化验证完成后，仍需在真实设备上验证网易云扫码风控、LRCLIB 网络可达性和双手机蓝牙链路。
